# `Z.原始证据` 与 `Z.待归类` 归类规则

---

## Z.原始证据 严格约束(每次执行优先级最高)

- **触发方式**:仅当用户手工将文件放入 `Z.原始证据/` 后,skill 才介入管理
- **铁律(原样保留 + 必须 OCR + 1.1 职责边界)**:
  - `Z.原始证据/` 内文件一律**禁止改动、改名、编辑、删除**,原样保留;
  - **必须对其内容执行只读 OCR 提取**,OCR 不得跳过——这是核心证据;
  - **1.1 的 OCR 职责 = 案件材料内容提取**:支持**全新提取**与**增量提取**,产物供**所有下游 skill** 读取;
  - **与 2.4-evidence-organizer 的职责区分**:2.4 在**上游 skill 完成后**,单独对原始证据整理时**再次 OCR**,目的是将不同格式原始文件**转为 PDF、合并为 PDF**;二者职责不同,不冲突、不重复。
- 移入时必须用 `shutil.move` + `os.utime` 还原时间戳
- skill **不主动**将根目录文件识别归入此目录,无法归类的统一进 `Z.待归类/`
- 目的:保持与客户原始文件的完全一致性

---

## Z.待归类 生命周期

- 有无法归类文件时自动建立,清空后自动删除,不常驻
- skill 不对此文件夹内文件做改名、移动或归类;但**必须对其内容执行只读 OCR 提取**(采用与 Z.原始证据 相同的零 token 优先 + 隐藏 .ocr.txt 机制,不改动原文件),OCR 不得跳过
- 日志记录"当前待归类文件数:N"

---

## 中置信度与无法识别的区分

来自操作计划阶段(详见 SKILL.md 第六部分),两类都进 `Z.待归类/`,但标注不同:

| 类型 | 标注 |
|------|------|
| 中置信度 | 附判断理由和建议选项 |
| 无法识别 | "无法识别,请人工处理" |
