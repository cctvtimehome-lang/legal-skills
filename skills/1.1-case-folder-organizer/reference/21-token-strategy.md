# Token 使用分层策略

核心原则:绝大多数工作由 Python 完成,LLM 只介入无法代码化的语义判断、视觉识别和用户交互呈现。

---

## 完整分层表

| 工作内容 | 执行方式 | LLM Token |
|---------|---------|-----------|
| 文件夹扫描、文件列表 | Python(analyze.py) | 0 |
| 快照对比、增量判断 | Python | 0 |
| MD5 重复文件检测 | Python | 0 |
| 传票日期/时间提取 | Python + pdfplumber 正则 | 0 |
| 传票生命周期检查(日期对比 + 自动移动) | Python | 0 |
| 合并 PDF 拆分:逐页文书类型识别 | Python + pdfplumber 关键词匹配 | 0 |
| 合并 PDF 拆分:无法识别页面 | 归入 Z.待归类,标注来源和页码 | 0 |
| 判决书/裁定书类型和审级识别 | Python + pdfplumber 正则 | 0 |
| 全角括号批量修复 | Python | 0 |
| 文件名从已知命名规律推断 | Python 正则 | 0 |
| 身份证:文件名中已有姓名 | Python 正则提取 | 0 |
| Z.原始证据:归类移入 | Python(保留时间戳移动) | 0 |
| Z.待归类:置信度分级判断 | Python 规则引擎 | 0 |
| `.case_index.json` 生成与更新 | Python | 0 |
| 身份证:乱码文件名扫描件 | LLM 视觉识别 | **少量** |
| 法院文书兜底归类 | OCR + LLM | **少量** |
| 审阅操作计划、用户确认 | LLM 呈现表格 | **少量** |

---

## 收益对比

- **零 token 工作**占总工作量约 90%
- **LLM 介入**仅限三类:视觉识别乱码文件名、兜底文书语义判断、用户交互
- 通过增量机制,重复运行时 95%+ 的文件直接跳过,不产生任何 token
